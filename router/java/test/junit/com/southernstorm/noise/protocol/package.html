The cipher states of the noise-java copy this tree carries under com.southernstorm.noise: {@code ChaChaPolyCloneIsolationTest}, which pins that cloning a {@code ChaChaPolyCipherState} copies its key, its {@code Poly1305} and its nonce counter instead of sharing them. Destroying the clone must leave the original holding a key and encrypting correctly - the state re-keys its authenticator per message, so a shared key would be zeroed under the original's feet - and both sides start at the same nonce but advance alone.

Only the public cipher-state API is used: {@code initializeKey()}, {@code setNonce()}, {@code encryptWithAd()}, {@code clone()} and {@code destroy()}. The expected tags are pinned known answers generated by the JDK's own ChaCha20-Poly1305, with the nonce in the last eight bytes of the IV, little-endian, as Noise defines it, so a regression cannot be confirmed by a second wrong implementation. They are constants rather than a live call because the build forks its test JVM on Java 8, which has no ChaCha20-Poly1305. Run by ant test in router/java.
