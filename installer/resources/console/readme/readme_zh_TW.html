• 啟動成功！
    如果您剛啟動I2P，側邊欄對等點區段下顯示的作用中對等點數量，會在接下來幾分鐘內開始增加。 您會看到一個本機目的地，名稱為分享客戶端，或許還有其他客戶端與伺服器。 如果沒有看到，請參閱下方的疑難排解部分。 這些本機目的地提供連到I2P網路的連線，讓您可以使用BT下載、電子郵件、網頁瀏覽與其他服務。 您的網路資料庫顯示網路上全部已知的對等點。 此外，您可以查看對等點資訊，並查看隧道以了解路由器的運作狀態。 說明頁面有更多資訊。
  • 網路整合
    當您啟動I2P後，可能需要幾分鐘的時間來引導（整合）您加入網路並尋找其他對等點，所以請耐心等待。（若您所在的網路環境限制嚴重，請考慮使用代理伺服器重新播種） 在正常運作期間，側邊欄的I2P隧道建立指示器可能會顯示“拒絕分享隧道”；這是正常的，在限制嚴格的國家，我們通常不會讓您為網路貢獻流量。 一旦您的本機目的地旁顯示綠色星星，您就可以使用I2P了，下面為您介紹幾件可以做的事：

I2P服務

  • I2P網站與明網瀏覽
    在I2P上您可以造訪I2P網站（“Eepsite”）與其他服務，也可以代管您自己的網站。 您也可以透過I2P內建的明網代理（出口代理）匿名造訪一般網路。 設定您的瀏覽器使用127.0.0.1:4444的HTTP代理，然後瀏覽I2P內部網站或一般網站。 如果您想停用或更改造訪一般網路的出口代理，請移除或修改隧道編輯器中I2P HTTP代理的出口代理選項。 在下方“有趣的網站”部分，我們列出了一些代管在I2P上的網站。
  • 匿名電子郵件
    Postman代管的I2P電子郵件，可以透過I2P內建的郵件客戶端或任何外部郵件客戶端造訪。 造訪hq.postman.i2p取得帳戶，此帳戶可以向一般網路收發郵件。 另外，I2P-Bote是I2P內部無伺服器、安全（端對端加密）的電子郵件系統，具有整合的匿名／假名回郵功能，並提供網頁介面與內建位址簿。（已停止開發） 它可以作為外掛安裝。
  • 匿名檔案傳輸
    I2PSnark已整合在I2P內，提供匿名加密的BitTorrent傳輸。
  • 匿名聊天
    啟動您的IRC客戶端（例如HexChat）並連線到127.0.0.1 6668連接埠上的IRC2P網路。 您不需要為IRC客戶端設定代理；I2P會提供本機IRC隧道（在您的IRC客戶端中顯示為IRC伺服器或遠端主機）。 您在localhost:6668上的本機I2P IRC隧道會指向由Postman、echelon與zl0代管在I2P上的三個IRC伺服器之一，但您與他們都不知道對方在哪裡，而且您的通訊在中繼時會由I2P加密以防止竊聽。 完成後，請到#i2p-chat和#i2p-dev看看！ 也有基於I2P的I2PChat可供不受監控審查的匿名聊天，以及其他人代管的IRC伺服器、Jabber伺服器、網站型聊天等等都可以尋找。 您可以選擇任何方式透過I2P執行自己的服務，如果您是開發者，也可以撰寫自己的I2P應用程式。 I2P同時支援UDP與TCP。 我們也提供了Java API的完整存取。
  • 論壇與部落格
    所有一般部落格、論壇與CMS軟體都能在I2P上執行，但我們建議您在設定時特別注意安全，並保持所有相關軟體（如PHP、MySQL、Python與Apache）為最新版本！ 此外，I2P上還有許多各種語言的社群論壇；請參閱下方取得一些建議。
  • I2P外掛
    透過安裝外掛擴充I2P的功能：部落格、聊天、檔案分享與其他外掛都已撰寫並移植，等著您的安裝！ 說明文件提供撰寫自己外掛的完整架構。

在I2P上代管服務

  • 內建網頁伺服器
    I2P內建的網頁伺服器讓您可以在I2P網路上代管自己的I2P網站（“匿名網站”）：一個Jetty實例監聽http://127.0.0.1:7658/。 若要代管您自己的內容，只需將您的檔案放在/eepsite/docroot/資料夾中（或將任何標準JSP/Servlet .war檔案放在eepsite/webapps下，或將標準CGI指令稿放在eepsite/cgi-bin下即可）。 您也可以執行其他網頁伺服器來取代內建的伺服器，或在另一條服務端隧道中執行。
  • 啟動您的隧道
    啟動後，您的預先設定的I2P伺服器隧道就會啟動，其他人便可以存取您的網站（但很難找到您的網站）。 註冊.i2p網域名稱以及向他人宣傳您網站的詳細說明，可以透過您自己的I2P網頁伺服器http://127.0.0.1:7658/help/查看。

疑難排解與更多說明

  • 請保持耐心！
    I2P第一次執行時，可能需要很長時間才能整合進網路，因為它必須啟動並尋找對等點。 您的I2P路由器運作越久，效能就越好，所以請盡量讓路由器持續運作，如果可能的話，24/7全天候最佳！ 如果30分鐘後，您的作用中對等點數量仍然少於10個對等點，或整合的對等點總數少於5個，您可以做幾件事來檢查問題：
  • 檢查您的組態與頻寬配置
    當您的頻寬配置設定正確時，I2P的效能最佳。 I2P預設的頻寬配置相當保守，並不適合許多使用情境，所以請花時間檢視這些設定並在必要時修正。 您配置的頻寬，尤其是上傳頻寬越多，您從網路獲得的效益就越大。
  • 防火牆、數據機與路由器
    如果可能，請適當設定您的數據機／路由器／電腦防火牆，確保允許I2P/Java從網際網路存取而不受防火牆限制。 如果您位於限制嚴格的防火牆之後，但具備不受限制的對外存取權限，I2P仍可運作；您可以關閉對內存取，改用SSU IP位址偵測（防火牆打洞）將您連上網路，此時側邊面板的網路狀態會顯示“網路：受到防火牆限制”。 為了最佳化效能，請確保I2P的外部連接埠可從網際網路存取。 請參閱下方詳細資訊。
  • 檢查您的代理設定
    如果您無法存取任何網站（甚至無法存取i2p-projekt.i2p），請確認您的瀏覽器代理設定為127.0.0.1:4444，類型為HTTP代理。 如果您需要協助，這裡有一份設定瀏覽器使用I2P的指南。
  • 檢查您的日誌
    日誌或許有助於解決問題。 您可能會想在我們的論壇貼上部分日誌來求助，或是貼上引用連結並在IRC上求助。
  • 驗證Java是否為最新版本
    請確認您的Java是最新的版本。 要求7或更新版本；建議使用8或更新版本。 請在日誌頁面頂端檢查您的Java版本。
  • 在舊式硬體上執行的問題
    [Linux/BSD]如果您無法使用i2p/i2prouter start啟動路由器，請改用同一資料夾中的runplain.sh指令稿。 執行I2P完全不需要root權限。 如果您需要編譯jBigi函式庫（僅在極少數情況下需要），請參閱說明文件、造訪論壇，或造訪我們的IRC開發者頻道。
  • 啟用通用隨插即用（UPnP）
    您的數據機或路由器可能支援UPnP自動連接埠轉送。 請確認您的數據機或路由器已啟用UPnP支援。 接著重新啟動I2P路由器。 一旦I2P路由器完成初始連線測試，如果成功，I2P應回報“網路：正常”。（若在受嚴格管制的網路環境中，也建議啟用UPnP，但這仍無法保證您不會被限制對內連線）
  • 連接埠轉送
    請在您的數據機、路由器及／或防火牆上開啟I2P的連接埠，以獲得更好的效能（若在受嚴格管制的網路環境中，請關閉TCP，這可能導致您的流量被偵測）。 關於如何進行連接埠轉送的更多資訊，很容易就能透過網路搜尋找到。 如果您有任何困難，可以在我們下列的論壇與IRC頻道尋求協助。 請注意，I2P不支援透過http或socks代理連線到網際網路，不過一旦連上網路，您可以透過I2P本身連線到出口代理，但那些是志願者運作的服務，並非I2P計畫的一部分。
  • 取得線上支援
    您可能需要在I2P網站上取得資訊，在I2P討論論壇上發表訊息，或在IRC2P網路上的#i2p或#saltR頻道諮詢。 這些頻道也可以透過Freenode IRC在I2P網路之外存取。
  • 回報錯誤
    請在github.com/I2PPlus/i2pplus/issues，或透過明網的i2pgit.org提交工單以回報錯誤。 若要進行開發相關的討論，請造訪zzz的開發者論壇或IRC2P網路上的開發者頻道。 開發者可在Github上瀏覽原始碼。
  • 一起參與！
    I2P的開發與維護主要靠社群成員的無偿自願參與。關於如何參與的更多資訊，可在官方網站的志願者頁面找到。
  • I2P+
    關於I2P+的更多資訊，請查看skank.i2p或i2pplus.github.io，或者加入IRC2P上的#saltR頻道。歡迎為I2P+貢獻程式碼，請透過以下方式提交合併請求：Gitlab或git.i2p。
