• شروع کرنا
    اگر I2P+ ابھی شروع کیا گیا ہے تو فعال peers کی تعداد، جو سائیڈ بار کے Pares سیکشن میں دکھائی جاتی ہے، اگلے چند منٹ میں بڑھنا شروع ہو جانا چاہیے، اور آپ کو مقامی مقصد نام کا Shared Clients بھی نظر آئے گا جو سروس ٹنلز سیکشن میں درج ہوگا، اور I2P کی ترتیبات کے مطابق ممکن ہے کہ دوسرے کلائنٹس اور سرورز بھی نظر آئیں۔ یہ مقامی مقاصد I2P نیٹ ورک میں مختلف پورٹس پر سروسز تک کنکشن فراہم کرتے ہیں، جس سے BitTorrent، ای میل، ویب پراکسی اور دوسری سروسز کام کرتی ہیں۔ آپ کی نیٹ ورک ڈیٹابیس نیٹ ورک میں مقامی طور پر معلوم تمام peers دکھاتی ہے۔ آپ موجودہ peers کی کنکشنز بھی مانیٹر کر سکتے ہیں، peer کی کارکردگی کے پروفائلز دیکھ سکتے ہیں اور فعال ٹنلز اور ان کی حالت دیکھ سکتے ہیں۔
  • نیٹ ورک میں اندماج
    پہلی بار I2P+ شروع کرنے پر نیٹ ورک میں شامل ہونے اور اندماج بہتر بنانے کے لیے اضافی peer تلاش کرنے میں چند منٹ لگ سکتے ہیں، اس لیے صبر کریں۔ سائیڈ بار میں مقامی مقاصد کے ساتھ سروس ٹنلز سیکشن میں سبز ستارے آنے کے بعد I2P+ کے ساتھ بہت سی کام کیے جا سکتے ہیں، جن میں سے کچھ نیچے دکھائے گئے ہیں۔
  • نیٹ ورک کی حالت
    I2P+ کو آپ کی نیٹ ورک کنیکٹیوٹی آزمالنے میں وقت ملنے کے بعد سائیڈ بار میں نیٹ ورک حالت کا اشارہ کم از کم "OK" دکھانا چاہیے۔ اگر حالت "Firewalled" بتاتی ہے تو I2P+ چلتا رہے گا مگر نیٹ ورک کی کارکردگی بہترین نہیں ہوگی، اور نیٹ ورک کو بینڈ وائٹ فراہم کرنے کی آپ کی صلاحیت محدود ہو جائے گی۔ بہترین کارکردگی کے لیے اپنا بیرونی پورٹ I2P+ اپنے فائر وال اور اپنے ISP کے فراہم کردہ روٹر میں کھولنے پر غور کریں۔ حالت کے پیغامات کے بارے میں مزید معلومات صارف انٹرفیس کی مدد کے صفحے پر دستیاب ہیں۔
  • پتہ کتاب سبسکرپشنز
    I2P+ کے لیے .i2p ہوسٹ نیمز خودکار طور پر حل کرنے کے لیے بنیادی طور پر ایسی سروسز کی سبسکرپشنز درکار ہیں جو معلوم ہوسٹس کے لیے DNS ترجمہ فراہم کرتی ہیں۔ اگر آپ نے I2P سے اپ ڈیٹ کرنے کے بجائے I2P+ انسٹال کیا ہے تو پہلے سے کافی پتہ کتاب سبسکرپشنز ترتیب شدہ ہوں گی؛ انسٹال ہونے کے بعد آپ کی پتہ کتاب بغیر کسی مداخلت کے نیٹ ورک میں فعال سروسز کے ہوسٹ نیمز سے بھر جانا شروع ہو جائے گی۔ اگر آپ نے I2P سے اپ ڈیٹ کیا ہے تو پتہ کتاب سبسکرپشنز سیکشن عام سوالات میں دیکھیں تاکہ اضافی سبسکرپشنز شامل کرنے میں مدد ملے۔
  • براؤزر کی ترتیبات
    نیٹ ورک پر ویب سائٹس دیکھنے کے لیے اپنے براؤزر کو پورٹ 4444 پر ترتیب شدہ طے شدہ HTTP پراکسی استعمال کرنے کے لیے ترتیب دینا ہوگا، جو ایک outproxy بھی فراہم کرتی ہے اور اس کی بدھ clearnet سائٹس کی گمنیم نیویگیشن کی اجازت دیتی ہے۔ Firefox ترتیبات کی مختصر رہنمائی مدد سیکشن کی ترتیبات صفحے پر دی گئی ہے، یا مختلف براؤزر کی ترتیبات کی رہنمائی کا لنک حاصل کرنے کے لیے نیچے دیا گیا سیکشن دیکھیں۔ اپنا براؤزر اور پتہ کتاب سبسکرپشنز ترتیب دینے کے بعد notbob.i2p نیٹ ورک پر مواد دریافت کرنے کے لیے ایک بہترین سائٹ ہے۔

I2P میں سروسز

  • غیر نظر آنے والی عوامی انٹرنیٹ پر نیویگیشن
    I2P میں آپ I2P پر میزبان شدہ ویب سائٹس ("eepsites") تک رسائی حاصل کر سکتے ہیں یا I2P میں شامل ویب پراکسی (outproxy) کے ذریعے عام ویب کو گمنیم انداز میں دیکھ سکتے ہیں۔ اپنا براؤزر ترتیب دیں تاکہ وہ 127.0.0.1 پورٹ 4444 پر HTTP پراکسی استعمال کرے، پھر کسی پوشیدہ سروس کی ویب سائٹ یا http:// سے غیر خفیہ کاری شدہ عام پتے پر جائیں۔ عام انٹرنیٹ outproxy تک رسائی غیر فعال یا تبدیل کرنے کے لیے false.i2p یا purokishi.i2p کا outproxy اندراج Outproxies سیکشن کے اندر ایڈٹ صفحے پر حذف یا ترمیم کریں، جو ٹنل مینیجر میں HTTP پراکسی کلائنٹ ٹنل کا ہے۔
  • گمنیم ای میل
    Postman کا I2P پر مبنی ای میل نظام I2P کے بلٹ ان میل کلائنٹ (SusiMail) یا کسی بھی معیاری میل کلائنٹ سے حاصل کیا جا سکتا ہے۔ ایک میل گیٹ وے اجازت دیتا ہے کہ عام انٹرنیٹ پتوں سے میل موصول ہو؛ آپ کا @mail.i2p پتہ @i2pmail.org سے بھی رابطہ کیا جا سکتا ہے۔ اکاؤنٹ حاصل کرنے کے لیے hq.postman.i2p دیکھیں۔
  • گمنیم فائل منتقلی
    I2PSnark I2P میں شامل ہے اور گمنیم اور خفیہ کاری شدہ BitTorrent منتقلیات فراہم کرتا ہے۔ متبادل کے طور پر موجود ہے BiglyBT (Azureus/Vuze کا جانشین)، ایک BitTorrent کلائنٹ جو I2P کے ذریعے torrents کی معاونت کرتا ہے، اور XD، Go میں لکھا گیا ایک I2P کے لیے خصوصی BitTorrent کلائنٹ۔ اضافی سروسز میں براؤزر پر مبنی فائل ہوسٹنگ شامل ہے، جیسے cake.i2p اور fs.i2p۔
  • گمنیم چیٹ
    اپنا IRC کلائنٹ (مثلاً HexChat) شروع کریں اور سرور سے 127.0.0.1 پورٹ 6668 پر منسلک ہوں۔ آپ کو اپنے IRC کلائنٹ میں کوئی پراکسی ترتیب دینے کی ضرورت نہیں؛ I2P آپ کو ایک مقامی IRC ٹنل فراہم کرتا ہے (جسے آپ کے IRC کلائنٹ میں IRC سرور یا ریموٹ ہوسٹ کے طور پر ترتیب دیا جاتا ہے)۔ وہاں پہنچ کر #saltr اور #i2p-dev ان دستیاب چینلز میں سے چند ہیں جن میں آپ شامل ہو سکتے ہیں۔ I2P پر مبنی ایک کراس پلیٹ فارم فوری پیغام رسانی ایپلیکیشن بھی موجود ہے، جو Github پر دستیاب ہے۔
  • گمنیم اور خفیہ کاری شدہ ویب ہوسٹنگ
    I2P میں اپنی ویب سائٹ I2P نیٹ ورک پر میزبان کرنے کے لیے ایک ویب سرور شامل ہے: Jetty کا ایک انسٹنس http://127.0.0.1:7658/ پر سن رہا ہے۔ پری سیٹ I2P ویب سرور کا ٹنل شروع کرنے کے بعد آپ کی سائٹ دوسروں کو نظر آئے گی (مگر قابلِ دریافت نہیں ہوگی)۔ اپنی سائٹ ترتیب دینے اور .i2p ڈومین رجسٹر کرنے کے ہدایات مدد سیکشن میں دی گئی ہیں۔
  • I2P کے لیے پلگ انز
    کئی پلگ انز براہ راست ڈاؤن لوڈ کرنے کے لیے zzz پلگ ان صفحہ دیکھیں۔ اگر آپ ڈویلپر ہیں تو اپنے پلگ انز لکھنے کے لیے زبان سے آزاد فریم ورک فراہم کیا گیا ہے۔

ڈویلپرز اور تعاون کنندگان کے لیے معلومات

  • خرابیاں رپورٹ کریں
    خرابی رپورٹ کرنے کے لیے براہ کرم github.com/I2PPlus/i2pplus/issues پر ٹکٹ درج کریں۔ ڈویلپرز سے متعلق بحثوں کے لیے براہ کرم zzz ڈویلپر فورمز دیکھیں یا ڈویلپر چینل (#i2p-dev) دیکھیں، جو I2P کی IRC نیٹ ورک پر ہے۔
  • I2P میں ترقی
    اگر آپ ڈویلپر ہیں تو آپ اپنی I2P ایپلیکیشنز لکھنے کا سوچ سکتے ہیں یا I2P نیٹ ورک کا فائدہ اٹھا کر اپنی ایپلیکیشن کی سیکیورٹی بہتر کر سکتے ہیں۔ UDP اور TCP دونوں پروٹوکول فراہم کیے گئے ہیں، اور ریئل ٹائم سٹریمنگ بھی ممکن ہے۔ ہم Java API تک مکمل رسائی بھی فراہم کرتے ہیں، اور I2P کی بنیادی لائبریریز Apache Maven ریپازٹری پر موجود ہیں۔ ڈویلپرز ماخذ کوڈ Github (I2P) یا Github (I2P+) پر دیکھ سکتے ہیں، اور مسلسل انٹیگریشن پلیٹ فارم Travis (I2P) یا Gitlab (I2P+) کے ذریعے موجودہ بلڈ کی حالت دیکھ سکتے ہیں۔ ماخذ کوڈ سے بلڈ کرنے کے لیے ایک Java SDK اور Apache Ant درکار ہیں۔
  • شریک ہوں!
    I2P کو بنیادی طور پر کمیونٹی کے ارکان کی خودکار اور غیر مالی شرکت سے تیار اور برقرار رکھا جاتا ہے۔ آپ کیسے شریک ہو سکتے ہیں، اس بارے میں مزید معلومات رضاکارانہ صفحے پر سرکاری ویب سائٹ میں دستیاب ہیں۔
  • I2P+
    I2P+ کے بارے میں مزید معلومات کے لیے براہ کرم skank.i2p یا i2pplus.github.io دیکھیں، یا #saltR چینل میں شامل ہوں جو I2P کی IRC نیٹ ورک پر ہے۔ I2P+ کے لیے پیچز قبول کیے جاتے ہیں؛ براہ کرم pull requests Gitlab کے ذریعے بھیجیں۔
